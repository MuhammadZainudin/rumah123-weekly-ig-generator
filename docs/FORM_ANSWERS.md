## 4. Key prompts and descriptions on AI usage

### What I built
A weekly pipeline that turns Indonesian property news into Instagram drafts in Rumah123's voice. GitHub Actions runs it every Monday 08:00 WIB: (1) pull the last 7 days from Google News RSS with 6 queries, (2) dedupe near-identical headlines and keyword-rank, (3) a curator LLM call picks 3 stories with different angles (market data, KPR education, engagement) and extracts the only facts the writer may use, (4) a writer LLM call produces hook, slides, caption, hashtags and a visual idea as JSON, (5) deterministic Python guardrails check length limits, banned guarantee phrases, competitor names, attribution, and that every number in the post exists in the extracted facts, (6) violations are fed back for one repair attempt, otherwise the post is flagged needs_human_fix, (7) drafts open as a pull request. Nothing is posted automatically because a property brand should not publish unreviewed statistics.

### How AI was used
Claude (Anthropic) was my coding assistant for the design and code, and it is the model inside the pipeline (curator and writer calls). I reviewed the output, ran the checks, and fixed what they found.

### Prompts (pasted as text)

SYSTEM PROMPT (prompts/system.md)
```
You are the social media strategist and copywriter for Rumah123, Indonesia's leading property platform.

BRAND VOICE
- Friendly, trustworthy, practical. Like a knowledgeable friend who understands property and money.
- Never pushy, never alarmist. Explain jargon in plain words (DP, SLIK OJK, take over, yoy).
- Light humor is welcome. Forced slang and clickbait are not.

HARD RULES
1. Write in casual Bahasa Indonesia.
2. Use ONLY facts and numbers that appear in the FACTS list you are given. Never invent or "round up" a statistic.
3. Always attribute a statistic to its source (for example "Survei Bank Indonesia", "data BI", "Kontan").
4. No promises or guarantees: no guaranteed approval, no guaranteed price rise, no guaranteed returns, no "lowest rate".
5. No investment, legal or tax advice. General rules of thumb must be phrased with "umumnya" or "biasanya".
6. Do not mention or compare competitors.
7. Do not predict where prices or interest rates will go.
8. If the news is negative (sales down, rates high), stay calm and give the reader something practical to do.
9. Output valid JSON only, no commentary before or after.
```

CURATOR PROMPT (prompts/curator.md)
```
Below are {{COUNT}} property news candidates from the last 7 days (id, title, source, date, snippet).

TASK
Pick the {{N}} stories that would make the best Instagram posts for Rumah123 this week.

SELECTION CRITERIA
- Relevant to Indonesian home buyers, first-time buyers or KPR borrowers (age 25-40).
- Contains at least one concrete, checkable fact (a number, a rule change, a date).
- Prefer official or established sources (Bank Indonesia, OJK, ministries, major business media).
- Pick DIFFERENT angles. Aim for: (1) a market data update, (2) a practical KPR/finance education angle, (3) an engagement-friendly angle (a this-or-that style dilemma).
- Skip: pure corporate PR, promos from a single bank, paywalled items with no usable snippet, anything about competitors, anything where the snippet is too thin to extract a fact.

FOR EACH PICK return
- "id": the candidate id
- "format": "carousel" or "single"
- "angle": one sentence on the angle in Bahasa Indonesia
- "facts": 2-5 short factual statements copied or closely paraphrased from the snippet ONLY. Keep every number exactly as written. Do not add anything from your own knowledge.

If fewer than {{N}} candidates have enough substance, return fewer picks. Never pad with weak stories.

CANDIDATES
{{CANDIDATES}}

Return JSON only:
{"picks": [{"id": 0, "format": "carousel", "angle": "...", "facts": ["..."]}]}
```

WRITER PROMPT (prompts/writer.md)
```
Write ONE Instagram post for Rumah123.

AUDIENCE
Indonesians aged 25-35, first-time buyers, stable income, limited knowledge of mortgage terms.

STORY
Title: {{TITLE}}
Source: {{SOURCE}} ({{DATE}})
Angle: {{ANGLE}}
Format: {{FORMAT}}

FACTS (the only facts and numbers you may use)
{{FACTS}}

REQUIREMENTS
1. "hook": max 8 words, curiosity-driven, no clickbait.
2. If format is "carousel": 5-7 slides. Slide 1 repeats the hook. The last slide is a soft CTA to explore listings on Rumah123. Middle slides: one idea each, bold "title" (max 6 words) + "body" of 1-2 short sentences, with one actionable tip in at least two slides.
   If format is "single": "slides" is an empty list and "visual_idea" describes the single image (headline text + layout) in one or two sentences.
3. "caption": 80-120 words, short paragraphs, at most 6 emojis in total, no hashtags inside it.
   Structure: hook line -> what happened (with attribution) -> why it matters for a first-time buyer -> ONE engagement question that is easy to answer in a comment (A/B choice or "which one do you forget most?") plus a nudge to save or tag a friend -> soft CTA "Rumah123 (link di bio)".
4. "hashtags": 5-8, include #Rumah123, mix broad and niche.
5. "visual_idea": one line for the cover / image.
6. Do not repeat the same number in more than two places.

{{FEEDBACK}}

Return JSON only with exactly these keys:
{"hook": "", "format": "carousel|single", "slides": [{"title": "", "body": ""}], "caption": "", "hashtags": ["#Rumah123"], "visual_idea": ""}
```

### What went wrong (found by running it)
1. My first validator failed all three sample posts. It read the "123" in "Rumah123" as an unsourced statistic, and my own rules contradicted each other: the cover slide repeats the hook (max 8 words) but slide titles were capped at 6. I strip the brand name before extracting numbers and exempt the cover slide from the title limit.
2. While writing negative tests, the "statistic must be attributed" check passed when it should have failed. I matched "BI" as a lowercase substring, so the word "biaya" counted as a source. Fixed with whole-word matching, and short acronyms are case-sensitive. The same fix was applied to the competitor check.
3. The live RSS fetch returned 0 articles in my build environment (proxy 403) and my code failed silently. It now prints a warning per empty feed. Because of this the live path is untested end to end, and I used an offline fixture (data/sample_news.json, built from real articles, plus one synthetic duplicate headline to prove dedupe).
4. I had no API key in the build environment, so the curator and writer API calls have not been run through the script. The JSON extraction (_extract_json) is untested against real model replies and may need a small fix on the first real run.
5. Google News RSS gives only a headline and a short snippet, so facts are thin. The curator prompt tells the model to skip thin stories instead of guessing. The newest property survey I could find (7 Nov 2026) was Bank Indonesia's Q2 2026 release, so the sample posts need a freshness check before posting.

### What I would change
Fetch full article text or the Bank Indonesia press release page for richer facts; add a second LLM pass that fact-checks each post against the full source; use direct publisher RSS feeds instead of Google News redirects; generate the cover image from a brand template; pull Instagram insights back in to learn which hooks earn comments; and send drafts to Slack for approve/reject.
